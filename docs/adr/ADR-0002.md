# ADR-0002 — The Truth Model

This ADR defines **what is true and how truth is constituted**. It says nothing
about how the engine computes or caches. That is ADR-0003.

## Status

**Proposed.** Becomes binding when merged and when Milestone D14 (§10) passes.

> `src/timonelo/ontology/models.py` cites "ADR-0001" and `docs/ARCHITECTURE.md`
> links `adr/ADR-0001.md`. That file has never existed. This pair of ADRs is
> written to be governing documents enforced by tests rather than prose.

---

## 1. The constitutional principle

> **Evidence does not describe a value. It records how that value came into
> existence.**

Every defect in §2 follows from treating evidence as an attribute attached to a
value. Once evidence is an event record, attaching a source document to a
synthesized cabin is not a questionable assignment — it is an unwriteable
statement.

Everything below is a consequence of this sentence.

---

## 2. Context — audit findings, 2026-08-17

The codebase systematically manufactures certainty, contradicting the product's
public claim (`frontend/src/i18n/locales/en.ts:111`) that unverified details are
marked UNKNOWN.

1. **Synthesized geometry carries evidence.** `factory/archetype_generator.py`
   generates cabin polygons, areas, categories and bed positions arithmetically
   — `bed_near_balcony = (idx % 4 == 2)` — then assigns each generated cabin an
   `evidence_links` reference to a document that does not contain it.
2. **Defaults assert verification.** `database/evidence.py` defaults every
   `EvidenceField` to `status=VERIFIED, confidence=0.98,
   source="src:imo-gisis", verified_on="2026-08-16",
   reviewer="chief_knowledge_architect"`. Absence of provenance yields high
   confidence rather than none.
3. **Confidence from fabricated counters.** `EvidenceEngine.audit_ship()`
   increments `total_facts += 6` and `verified_count += 5` per cabin regardless
   of content. Fields lacking provenance count as `OFFICIAL`.
4. **Borrowed and forged provenance.** `factory/patch_engine.py` retains the
   base vessel's `evidence_links` on renamed and replaced venues; defaults
   `sha256` to sixty-four zeroes; and for a venue with no evidence, copies the
   evidence links of an arbitrary other venue on the same deck.
5. **Silent patch failure.** An operation targeting an unknown deck hits
   `continue`. No error, no log. The vessel renders as complete.
6. **No cabin patch operation.** Derivative vessels inherit one hundred percent
   of the reference vessel's staterooms, for a product whose central promise is
   knowledge of the user's cabin.
7. **Tests enforce the defect.** `test_assistant_engine.py` asserts
   `confidence_score >= 99.0`; `test_travel_intelligence.py` asserts `>= 90.0`.
   Lowering confidence for unsupported data turns CI red.

The primitives are sound — `EvidenceLink`, `EvidenceType`, `refit_version`,
`valid_from`/`valid_until` are the right shapes. The defect is semantic misuse.

## 3. Invariants

- **I1 — Confidence is never stored.** No schema may contain a writable
  confidence field. It is computed on traversal, every time.
- **I2 — Evidence records events, not values.** An evidence record states that
  an observation occurred: actor, instrument, document, locator, timestamp.
- **I3 — UNKNOWN is computed.** It is the absence of a statement satisfying a
  registered question. There is no UNKNOWN literal anywhere in the system.
- **I4 — Statement reproducibility.** See §4. Stronger than traceability, and
  distinct from the artifact determinism owned by ADR-0003.

---

## 4. I4 — Statement reproducibility

The engine is a **pure function of four inputs**:

```
answer = f(questions@version, events@version, rules@version, as_of)
```

Given identical inputs, the engine must always produce the identical statement.
Not merely an explanation of it. The statement itself.

### 4.1 `as_of` is an explicit parameter, never a clock read

Statements carry `valid_from` / `valid_until`. Which statements satisfy a
question therefore depends on *when the question is asked*. Without `as_of` as
an explicit input, identical Registry + Log + Rules produce different answers as
validity windows expire — and a correctly behaving system would violate I4.

Production reads the clock once, at the request boundary, and passes `as_of`
downward. No component beneath that boundary may read a clock.

This makes "what did we believe on 14 March" a query, not an archaeology
project.

### 4.2 Relationship to ADR-0003

I4 is **semantic** equality: the same claim, with the same derivation, at the
same strength. ADR-0003's determinism criterion is **byte** equality of the
built artifact.

These may diverge deliberately. Serialization may be refactored, breaking byte
equality, while every statement remains identical in meaning. That is a
permitted change under ADR-0003 and a non-event under ADR-0002. The reverse — a
statement changing meaning while bytes remain stable — is impossible, and if
observed indicates a defect in the closure tracking.

**Never repair a broken determinism test by modifying an inference rule.**

## 5. Stores

Three persistent stores. Everything else is derived and disposable.

| Store | Mutability | Contents |
|---|---|---|
| **Question Registry** | Versioned | Every question answerable about an entity type |
| **Evidence Event Log** | Append-only, immutable | Observation events |
| **Rule Set** | Content-addressed, versioned | Inference rules, each with a stable hash |

Derived, and owned by ADR-0003:

| Artifact | Derivation |
|---|---|
| **Ground Truth** | Fold over the Evidence Event Log |
| **Hypothesis Store** | Output of generators |
| **Inference Graph** | Materialized view (see ADR-0003) |

The log is append-only. Corrections are new events, never edits. "What did we
believe on date D" is a fold truncated at D.

### 5.1 Store separation is physical

Ground Truth and the Hypothesis Store **must not share a storage medium,
namespace, or type**. A generated cabin and a surveyed cabin must not be
constructible into the same collection.

Semantic separation depends on every future query remembering to check origin.
Eventually one will not. The type system must make the mistake unwriteable.

Promotion from hypothesis to ground truth requires an evidence event. There is
no automatic path.

## 6. Two orthogonal axes

`EvidenceStatus` is replaced. Two independent fields, never merged.

### 6.1 Method — how the statement was produced

| Value | Meaning | Confidence rule |
|---|---|---|
| `DIRECT` | Read from a source document or observed in the field | From source-reliability table |
| `CALCULATED` | Truth-preserving computation over inputs | `min(inputs)` |
| `INFERRED` | Defeasible rule application | `min(inputs) × rule.defeasibility` |

`ESTIMATED` is **not** adopted. It is either INFERRED at low confidence, or a
human guess — and a guess is a source, not a method. It may be introduced later
only with a written definition distinguishing it from both.

### 6.2 Derivation — where the inputs came from

| Value | Meaning |
|---|---|
| `LOCAL` | Inputs observed on this vessel |
| `SISTER_SHIP` | Inputs observed on a sister vessel |
| `REFERENCE_MODEL` | Inputs from the class reference model |
| `GENERATED` | Inputs synthesized; hypothesis only |

The axes are independent. `CALCULATED + SISTER_SHIP` — a distance computed from
a sister vessel's plan — is valid, expected, and inexpressible in a single enum.

## 7. Confidence propagation

Confidence is a **min-lattice** quantity. These are semantic rules; their
implementation and caching belong to ADR-0003.

```
DIRECT      → source_reliability[source_class]
CALCULATED  → min(confidence(i) for i in inputs)
INFERRED    → min(confidence(i) for i in inputs) × rule.defeasibility
```

A truth-preserving transformation cannot exceed the certainty of its premises.

### 7.1 Confidence is ordinal, not probabilistic

`0.63` means "weaker than the 0.7 class." It does **not** mean a 63 percent
likelihood. Two binding consequences:

- **No corroboration under propagation.** Independent sources agreeing may only
  raise confidence at the `DIRECT` layer, via an explicit rule with declared
  independence assumptions. Min-propagation never rewards agreement.
- **The number is never rendered.** See §9.

### 7.2 Ceiling on documentary sources

Cruise line deck plans are undated marketing artifacts, revised at refit, and
wrong often enough that `EvidenceConflict` exists to model the discrepancy.
Capped at `0.97`. Confidence `1.0` is reserved for tautologies.

A statement outside its validity window does not degrade gracefully. It ceases
to be a statement.

## 8. UNKNOWN by construction

The Truth Engine never asks "what do we know?" It asks, for a registered
question: **which statements currently satisfy this?**

```
unknown(entity, question, as_of) := no statement in the graph
                                    satisfies question for entity at as_of
```

No special case, no literal, no authored UNKNOWN.

### 8.1 Coverage as the primary KPI

```
coverage(vessel, as_of) = questions answerable / questions registered
```

A vessel with fifty thousand generated facts and no evidence events scores
zero. This is the correct result.

`database/gap_analyzer.py` computes gaps from data present. It must be
reoriented to compute against the registry.

## 9. The Language Layer is part of the truth contract

Presentation is not downstream of truth. It is where truth is most easily
destroyed: a `0.63 INFERRED` statement rendered as "Morning noise possible"
reads to a passenger as a fact about their cabin.

Binding constraints, testable rather than stylistic:

- **The Language Layer may never strengthen a claim.** Rendered hedging must be
  a function of computed confidence and method. Low-confidence INFERRED
  statements may not produce unhedged declarative sentences.
- **Confidence values are never rendered as numbers.** Decimals read as measured
  probability. Bands only; the derivation chain available on request.
- **UNKNOWN must be visible.** A question with no satisfying statement renders
  as an explicit gap, never as silence. A hidden UNKNOWN is indistinguishable
  from a question never asked.

### 9.1 Explanation is a transformation

The engine must always be able to answer **"why do you believe this?"** — not by
generating prose, but by returning the derivation graph.

- **The raw derivation graph is the canonical artifact.** It must be returnable
  unrendered, for auditors and for maintainers.
- **Every human-readable explanation is a deterministic rendering of that
  graph.** No explanation may ever be composed independently of it. Two
  independently-produced explanations diverge, and the divergence is invisible.
- **An explanation renderer may not strengthen a claim.** It is bound by the
  same constraints as any other Language Layer transformation.

Explainability is therefore never an AI feature. It falls out of the graph or it
does not exist.

## 10. Milestone D14 — one deck, one ship, fully traceable

No generalization begins until this passes. Deliberately not optimizing for
generality.

**Scope.** One deck of one vessel, containing cabins, a lift core, and at least
one noise-generating venue vertically adjacent to a cabin — so that `DIRECT`,
`CALCULATED` and `INFERRED` are all exercised. A deck without a noise adjacency
proves nothing about the defeasible path, which is the only path that needs the
confidence machinery.

**Conditions.**

1. Zero synthesized geometry in Ground Truth for that deck.
2. Zero borrowed provenance. Every evidence link resolves to a document
   containing the cited claim at the cited locator.
3. Every rendered statement inspectable to its full derivation chain.
4. Every registered question returns a satisfied statement or UNKNOWN. No third
   outcome.

Acceptance tests for determinism and blast radius are specified in ADR-0003.

**Open decision:** which deck. Requires judgment about which plans are actually
obtainable in verifiable form.

### 10.1 The generality rule, and its carve-out

> No architectural concept survives unless it successfully models one real deck
> end-to-end.

Applied literally this rule would retire the abstractions that were hardest to
get right, because several cannot be exercised by one deck of one ship *by
construction*: `SISTER_SHIP` derivation requires a second vessel; rule
versioning requires a rule to change over time; validity windows require two
distinct `as_of` values. These exist to prevent future silent wrongness and are
invisible to a present-coverage test.

The binding form is therefore:

> **Every abstraction must either be exercised end-to-end by D14, or carry a
> written justification for why D14 cannot exercise it and which milestone
> will.**

This preserves the discipline — no unjustified generality — without allowing
"it did not help with deck 14" to retire something that exists for ship forty.

## 11. Consequences

### 11.1 Accepted costs

**Coverage collapses on publication.** If reference-vessel cabin geometry was
produced by `archetype_generator` — and the audit indicates it was — then on the
day this lands, the fleet has zero cabins backed by ground truth, and nearly
every passenger question correctly returns UNKNOWN.

This is not a regression. It is the first accurate measurement the system has
produced. The engine was always this empty; it was reporting 0.98.

Also accepted: duplicate storage between Ground Truth and Hypotheses, over
reliance on developer discipline.

### 11.2 Required changes

| Target | Change |
|---|---|
| `database/evidence.py` | Invert defaults: `status=UNKNOWN`, `source=None`, no default date, no default reviewer; **remove `confidence` from the schema entirely** |
| `database/evidence.py` | Delete `audit_ship()` fabricated counters; no-provenance must not count as `OFFICIAL` |
| `ontology/models.py` | `EvidenceLink` becomes a reference to an evidence event, not a value attribute |
| `ontology/models.py` | Concept identifiers become opaque; English becomes a label (§12) |
| `factory/archetype_generator.py` | Output routed to Hypothesis Store; `evidence_links` assignment removed |
| `factory/patch_engine.py` | Unknown deck raises rather than `continue`; no default `sha256`; no borrowed evidence links; no default polygons or entrance nodes |
| `factory/patch_engine.py` | Add cabin operations; wholesale cabin inheritance prohibited |
| `database/gap_analyzer.py` | Reorient from data-present to registry-comparison |
| `tests/test_assistant_engine.py` | Remove `confidence_score >= 99.0` |
| `tests/test_travel_intelligence.py` | Remove `confidence_score >= 90.0` |
| `tests/` | Add: unsupported data never attains confidence above zero |
| `tests/` | Add: Language Layer never strengthens a claim (§9) |

### 11.3 Sequencing

1. Invert `evidence.py` defaults. Everything that breaks was silently invented.
2. Evidence-as-event refactor.
3. Question Registry; UNKNOWN by construction.
4. Confidence propagation; delete all stored confidence.
5. Store split; hypothesis quarantine.
6. Rule content-addressing.
7. ADR-0003 runtime work.
8. Milestone D14.
9. Only then: further vessels, visual polish.

The origin taxonomy (§6) is deliberately late. Cheap once the derivation graph
exists; expensive to retrofit onto a flat model.

## 12. Forward-compatibility note — canonical vocabulary

Not for implementation now. Recorded so the architecture leaves room.

Eventually Questions, Evidence, Rules and domain terms will require a canonical
concept vocabulary. *Lift*, *Elevator*, *Ascenseur*, *Aufzug* must map to one
concept. Multiple cruise lines use divergent naming for identical structures.

**One part is today's problem.** Question identity leaks into every satisfaction
record ever written. If questions are keyed by English strings, the eventual
vocabulary layer becomes a migration across the entire statement graph.

Therefore, binding now:

- **Questions carry opaque stable IDs.** `Q-0041`, with `label.en` as
  presentation metadata. Never keyed by English text.
- **Concept enums carry opaque identifiers.** `VenueCategory.BAR_LOUNGE` is
  already English-as-identifier and is already debt — small enough to fix now,
  expensive after the graph is populated.

Everything else about vocabulary is deferred to a future ADR.

## 13. Out of scope

- **Crew-sourced knowledge.** Non-reproducible; collides with I4. Requires a
  separate trust track, its own ADR, and assessment of employment and NDA
  exposure for contributors.
- **Volatile domains** — weather, visa, currency, transit. Different validity
  semantics from quasi-static geometry; sharing a confidence model dilutes it.
- **Source document redistribution.** Extracted facts (deck number, cabin
  position) are not protectable and may be published. Deck plan images and
  substantially reconstructed renderings are. Since evidence events reference
  documents by locator, a decision is required on whether source PDFs are stored
  or only cited. Flagged, not decided.
