# ADR-0004: Every Visual Decision Is An Epistemic Claim

**Date**: 2026-08-17
**Status**: `PROPOSED`

---

## Context

The Semantic Deck is not a geometric model. It is an epistemic projection: a
visual statement about what is known, not about what things look like.

Uniform spacing already encodes this. It says *we know order, we do not know
distance*. Equal cell sizes say *we know identity, we do not know dimensions*.
Both are scientific statements dressed as layout choices.

The corollary is the part that requires enforcement: **a renderer cannot
abstain.** Every element must be placed somewhere, at some size, in some order.
There is no null rendering. Every visual variable therefore carries a claim
whether or not the author intended one, and unintended claims are the dangerous
kind — nobody reviews them.

## Evidence that this is not theoretical

The first Semantic Deck render (deck 14, 2026-08-17) made two claims the Truth
Engine had explicitly refused:

1. **Orientation.** Blocks were stacked vertically in drawn page order and
   placed left-to-right mirroring page position. A reader reads vertical as
   fore/aft and horizontal as port/starboard. But `cabin.hull_side` is UNKNOWN
   for every curated cabin: the deck plan prints no port/starboard label, and
   deriving it requires the bow direction, which is not printed either. The
   renderer asserted what the statement store declined to assert.

2. **Block extent.** Block D14-B27 rendered shorter than D14-B35 because it
   holds six cabins rather than eight. Cell count is topological; rendered as
   height it reads as physical extent.

Both passed unnoticed through a review that was specifically looking for
fabricated geometry.

## Decision

Every renderer must declare, for each visual variable it uses, either the
epistemic claim it encodes or an explicit nullification.

The audited variables:

| Variable | Claim if unaudited | Required declaration |
|---|---|---|
| Position along an axis | Spatial arrangement in ship space | What the axis encodes, or that it is arbitrary |
| Distance between elements | Physical separation | Nullified by uniform spacing |
| Element size | Physical dimensions | Nullified by uniform size |
| Group extent | Physical extent of the group | Cardinality only, stated |
| Order within a group | Sequence in space | Ordinal from topology, orientation unstated |
| Left/right, top/bottom | Port/starboard, fore/aft | Must be nullified unless evidenced |
| Colour | Category membership | What it maps to |
| Border pattern | Epistemic state | Which state |
| Absence of an element | The object does not exist | Must render as explicit gap |

A render that uses a variable without a declaration is a defect, regardless of
how the output looks.

## Consequences

**Orientation must be nullified until it is evidenced.** Axis labels must state
that the axis is ordinal and that fore/aft and port/starboard are unknown. A
renderer may not silently inherit the publisher's page orientation — page
position is not ship position, and carrying it over reintroduces the
publisher's geometry through layout rather than through coordinates.

**Group extent must not scale with cardinality** where extent could read as
physical size, or the reading must be defused by an explicit label.

**Absence is a claim.** A deck rendered with only its curated cabins claims
those are the only cabins. Uncurated objects render as explicit gaps.

**The renderer is part of the scientific method, not downstream of it.** A
render is reviewable output like a statement is, and a visual claim that
contradicts the statement store is the same class of defect as a fabricated
statement.

## Compliance

`src/renderer/audit.py` provides `RenderAudit`. A renderer constructs one,
declares each variable it uses, and calls `assert_complete()` before emitting.
Undeclared variables raise. The audit is serialized alongside the render so a
reviewer sees the claims without reading the drawing code.
